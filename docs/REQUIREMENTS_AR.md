# متطلبات مشروع نبض — SocialPulse

## الغرض والنطاق
منصة بحث في المحتوى **العام المتاح قانونيًا** عن أسماء أشخاص مشهورين أو علامات تجارية أو كلمات، مع عرض منشورات وتعليقات وصور/روابط فيديو، وتحليل انطباعات وصفي غير ممثل للرأي العام بالضرورة.

## المستخدم والسيناريو
يدخل المستخدم اسمًا أو عبارة؛ يختار المصادر والفترة؛ يحصل على المنشورات المطابقة ومؤلفيها وروابطها وتعليقاتها العامة ووسائطها المتاحة، ثم توزيع تقريبي للمشاعر ومصادر النقاش وتصدير النتائج.

## المتطلبات الوظيفية
- FR01: البحث عن كلمة/اسم، مع ترتيب النتائج وتوضيح المصدر والعدد المسترجع.
- FR02: عرض اسم الحساب ومعرّفه والرابط الأصلي والتاريخ والنص والتفاعل إن توفر.
- FR03: عرض صور المنشور المصغرة وروابط الفيديو المسموح بها؛ لا ضمان لتنزيل ملفات الفيديو.
- FR04: تحميل التعليقات/الردود العامة مع كشف القيود والتصفح/الصفحات إن دعمها المصدر.
- FR05: إظهار تصنيف إيجابي/محايد/سلبي مع تنبيه على الدقة، وعدم اعتبار النتيجة رأيًا عامًا شاملًا.
- FR06: تصدير العينة المصفاة بصيغتي CSV وJSON مع بيانات المصدر والتوقيت.
- FR07: توحيد البيانات من مصادر متعددة مع إسناد المصدر وتجنب التكرار.
- FR08: معايير زمنية/بحث باللغة العربية واللهجات وتحديد أسباب المشاعر لاحقًا.
- FR09: مؤشرات الاستخدام والتنبيه للأخطاء وعدم اختلاق النتائج.

## متطلبات غير وظيفية
- NFR01 الأمان: HTTPS، قيود معدل الطلبات، التحقق من المدخلات، التحكم بالأسرار، سجل أخطاء من دون بيانات حساسة.
- NFR02 الخصوصية: محتوى عام فقط مع احترام سياسات المنصات والقانون والاحتفاظ والحذف وحقوق الأفراد.
- NFR03 الاعتمادية: وقت انتظار واضح، إعادة محاولة محدودة، مراقبة المصدر، اختبارات آلية.
- NFR04 التكلفة: عدم الالتزام بمدفوعات إلا بموافقة؛ تسجيل حدود الخطط المجانية.
- NFR05 الوصول: واجهة عربية RTL وملائمة للجوال وقابلة للاستخدام بلوحة المفاتيح.
- NFR06 الشفافية: التاريخ والمصدر وحجم العينة والاستثناءات وعدم التعميم.

## تكاملات البيانات
| الخدمة | الحالة | المصادقة | الملاحظات |
|---|---|---|---|
| Bluesky public XRPC | مدمجة بالكود | لا يحتاج مفتاحًا لبعض القراءة العامة | يلزم اختبار حي؛ API قد يقيّد الوصول |
| YouTube Data API | مخطط | مفتاح API/حصة مجانية | التعليقات قد تُغلق أو لا تتوفر |
| TikTok | غير مربوط | يختلف حسب وصول المطور | البحث العام الشامل ليس مضمونًا |
| Instagram | غير مربوط | Meta permissions | قيود قوية على وصول محتوى الآخرين |
| X | غير مربوط | وصول API حسب الخطة | لا يُفترض أنه مجاني أو شامل |
| Reddit | غير مربوط | وصول وشروط مطور | قيود الاستخدام التجاري والبيانات |

## نموذج البيانات المستهدف
- `Source`: المنصة، طريقة التجميع، وقت الجمع، حالة الوصول.
- `Author`: معرّف عام، اسم ظاهر، رابط ملف عام، بيانات متاحة فقط.
- `Post`: معرّف، مصدر، نص، تاريخ، رابط أصلي، إحصاءات، مؤلف.
- `Comment`: معرّف، منشور أب، كاتب، نص، توقيت، مستوى الرد.
- `Media`: نوع (صورة/فيديو)، رابط معاينة، رابط مصدر، صلاحية عرض.
- `Sentiment`: تصنيف، طريقة تحليل، ثقة/قيود، اللغة.
- `SearchJob`: عبارة، مرشحات، تاريخ تشغيل، نتائج، أخطاء، مقدار التغطية.

## معايير النشر
1. تشغيل اختبارات محلية ثم اختبار اتصال API خارجي حي.
2. رفع الكود إلى GitHub بعد منح التطبيق إذن `Contents: Read and write`.
3. نشر Worker على Sites عبر HTTPS (مع الإبقاء على Python للتشغيل المحلي)؛ **GitHub Pages وحده لا يشغّل `server.py`**.
4. فحص المسارات `/`, `/api/status`, `/api/search`, `/api/thread` مع بيانات عامة ونتائج حقيقية.
5. إضافة تحكم بالاستخدام وسياسة خصوصية قبل الإتاحة العامة.

## حدود الإصدار الحالي
الإصدار ٢ يتصل بـ Bluesky فقط، مع فلاتر تاريخ ولغة وصفحات وتصدير CSV وJSON وحفظ عبارات البحث محليًا. لا توجد قاعدة بيانات للمنشورات أو جدولة. تحليل المشاعر قاموسي ومحدود الدقة. نجح نشر Sites خاص بصاحب الحساب عبر HTTPS؛ فحص واجهة المتصفح والبحث الحي لم يكتمل بسبب بوابة تسجيل الدخول. رفض تكامل GitHub الرفع بخطأ 403. راجع DELIVERY.md للأدلة.
